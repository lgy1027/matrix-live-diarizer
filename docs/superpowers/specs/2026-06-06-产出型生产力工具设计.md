# 产出型生产力工具 — 设计文档

> **项目**: Matrix Live Diarizer
> **版本**: v0.2
> **日期**: 2026-06-06
> **状态**: 已通过设计评审，待实施

---

## 1. 一句话定位

**数据永远不出本机的本地音频转写工具。** 把"转写"做成"产出"：既能像字幕软件一样批量转写并导出 SRT/VTT/Markdown/JSON，也能像实时字幕一样处理麦克风；转写历史默认本地存档，统计说话人时长；高级能力（摘要、纪要、行动项）通过可选本地 LLM 插件实现，没装 LLM 也能用基础能力。

---

## 2. 目标与非目标

### 2.1 目标

| 目标 | 验收标准 |
|---|---|
| 支持实时与批量两种场景 | WebSocket 流 + 文件上传，共享同一推理内核 |
| 100% 本地部署 | 一次安装后完全离线运行；首次启动后断网可用 |
| 数据不外泄 | 启动 + 运行时不调用任何公网 API；LLM 仅允许内网/本机 |
| 多格式导出 | 同一转写可导出 SRT / VTT / Markdown / JSON |
| 自动产出统计 | 说话人时长占比、字数、hot words、静音比 |
| 高级 AI 能力可选 | 摘要 / 行动项 / 会议纪要，未装 LLM 时优雅降级 |
| 转写历史可回溯 | 默认本地存档；可关闭 |
| 用户可控的隐私开关 | 模型预下载、LLM endpoint、存储开关、清理策略 |

### 2.2 非目标

- **明确不做**：云同步、云存储、云处理
- **暂保留**：多用户、移动端、付费 — 未明确否决
- **范围外**：GPU 批处理（用户量级未到）、流式 ASR（qwen-asr 流式能力需 PoC）、敏感词检测

## 3. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 用户 | 多场景（实时 + 批量） | 项目名 "Live" 暗示实时，但 README 明确支持上传；维持现状 |
| 部署 | 本地单机 | 降低复杂度、保证隐私、零运维 |
| 护城河 | 完全离线 + 隐私 | 与云服务（Otter/Sonix）形成差异化 |
| 演进路径 | 产出型生产力工具 | 把"转写"做成"产出"，扩大价值半径 |
| LLM 策略 | 可选本地 LLM 插件 | 用户可装可不装；用 OpenAI 兼容协议兼容多后端 |
| 历史存储 | 默认存 + 可关闭 | 隐私优先 + 用户控制 |
| 前端 | 拆为多页 + 路由 | 易于组织；保持纯静态部署 |
| 持久化 | 新增 SQLite（不含声纹向量） | ChromaDB 继续存向量，SQLite 存元数据 + 文本 |
| 前端框架 | 不引入 | 保持纯 HTML + 原生 JS；Alpine.js 作为可选 v0.3 |
| 导出协议 | 同步 HTTP 流 | 单次导出秒级返回，无需任务队列 |

### 4.2 数据流

**实时转写 → 存档 → 导出**：
```
WebSocket 接收 PCM
  → ASREngine.run_asr() → text
  → SpeakerEngine.compare_and_identify() → speaker_id
  → SessionContext.get_incremental_text() → incr_text
  → 推送给前端
  → [新] TranscriptRepository.save_segment()
       INSERT INTO segments (session_id, idx, speaker_id, text, start, end)
```

**文件上传 → 导出**：
```
POST /v1/upload (multipart)
  → 校验 + 存盘
  → 短音频：直接 ASR + Speaker → SegmentResult
  → 长音频：分段 → 多次 ASR+Speaker → 合并文本
  → [新] TranscriptRepository.save_session() 批量插入
       返回 session_id
  → 前端跳转到 detail.html?id=session_id
```

**导出**：
```
GET /v1/exports/{id}?format=srt
  → TranscriptRepository.get_session(id) → Session
  → TranscriptRepository.get_segments(session_id) → list[Segment]
  → services/exporter.export(segments, format=...)
  → StreamingResponse(media_type="text/plain", 
                      headers={"Content-Disposition": "attachment;filename=xxx.srt"})
```

**LLM 调用**：
```
POST /v1/llm/summarize {session_id}
  → 检查 LLMGateway.is_available()
  → 若不可用：返回 503 + 提示
  → 加载 segments → 拼 prompt → 调本地 LLM
  → 流式返回（SSE 或 WebSocket）→ 前端渲染
```

## 5. 数据模型（SQLite schema）

```sql
-- 转写会话（一次实时会话 或 一次文件上传 = 一行）
CREATE TABLE sessions (
    id            TEXT PRIMARY KEY,           -- UUID
    source        TEXT NOT NULL,               -- 'websocket' | 'upload'
    title         TEXT,                        -- 用户可改名
    client_id     TEXT,                        -- WebSocket client_id
    original_filename TEXT,                    -- 上传时的文件名
    duration_sec  REAL,
    speaker_count INTEGER DEFAULT 0,
    is_archived   INTEGER DEFAULT 0,
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_sessions_created ON sessions(created_at DESC);
CREATE INDEX idx_sessions_source  ON sessions(source);

-- 单个转写片段
CREATE TABLE segments (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id    TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    segment_index INTEGER NOT NULL,
    speaker_id    TEXT,
    text          TEXT NOT NULL,
    start_time    REAL NOT NULL,
    end_time      REAL NOT NULL,
    confidence    REAL,
    is_final      INTEGER DEFAULT 1
);
CREATE INDEX idx_segments_session ON segments(session_id, segment_index);

-- 说话人别名（与 ChromaDB 解耦）
CREATE TABLE speaker_aliases (
    speaker_id    TEXT PRIMARY KEY,
    display_name  TEXT NOT NULL,
    color         TEXT,
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 用户设置（K/V）
CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

**ORM**：SQLAlchemy 2.x Core（不是 ORM）。理由：项目已有 dataclass 风格配置、schema 简单、需要透明 SQL 调试。

**生命周期**：
- 默认所有会话都保存（可通过 `settings.history_enabled=false` 关闭）
- 7 天后提醒清理（v0.3）
- 手动删除单条会话 → CASCADE 自动清 segments

**与 ChromaDB 关系**：
- ChromaDB 只存声纹向量 + `name` 字段
- `speaker_aliases.display_name` 是用户改名的显示名
- 前端优先用 `display_name`，没有则用 ChromaDB 的 `name`

## 6. 模块设计

### 6.1 `services/exporter.py` — 4 种输出格式

**输入**：
```python
@dataclass
class ExportRequest:
    session: Session
    segments: list[Segment]   # 已按 segment_index 排序
    speaker_aliases: dict[str, str]
    options: ExportOptions
```

**4 个格式的输出示例**（同一段录音）：

#### SRT
```
1
00:00:00,000 --> 00:00:03,500
[Speaker 1] 你好

2
00:00:03,500 --> 00:00:07,200
[Speaker 2] 你好，请坐
```

#### WebVTT
```
WEBVTT

1
00:00:00.000 --> 00:00:03.500
<v Speaker 1>你好</v>

2
00:00:03.500 --> 00:00:07.200
<v Speaker 2>你好，请坐</v>
```

#### Markdown
```markdown
# 项目周会
**Date**: 2026-06-06 14:30  
**Duration**: 12:34  
**Speakers**: 3

---

## Speaker 1

- **[00:00]** 你好
- **[00:05]** 接下来我们讨论...

## Speaker 2

- **[00:03]** 你好，请坐
```

#### JSON（无损）
```json
{
  "session": {"id": "...", "title": "...", "duration_sec": 754.2, ...},
  "speakers": [{"id": "Spk_001", "display_name": "张三", ...}],
  "segments": [
    {"index": 1, "speaker": "Spk_001", "text": "你好",
     "start": 0.0, "end": 3.5, "confidence": 0.95}
  ]
}
```

**关键设计点**：
- 格式通过 query string 控制：`GET /v1/exports/{id}?format=srt`
- 多说话人策略：SRT/VTT 文本前加 `[Speaker Name]`；Markdown 分组
- 时间码精度：SRT 用毫秒（`,` 分隔），VTT 用毫秒（`.` 分隔）
- 空文本段跳过
- 超长段（>5s）可选按标点二次切分（v0.3）

### 6.2 `services/statistics.py` — 规则统计

**输入**：segments + speaker_aliases
**输出**：
```json
{
  "total_duration_sec": 754.2,
  "speech_duration_sec": 612.5,
  "silence_duration_sec": 141.7,
  "silence_ratio": 0.188,
  "speakers": [
    {
      "speaker_id": "Spk_001",
      "display_name": "张三",
      "talk_time_sec": 320.4,
      "talk_ratio": 0.523,
      "segment_count": 47,
      "word_count": 612,
      "avg_segment_sec": 6.82
    }
  ],
  "hot_words": [
    {"word": "项目", "count": 23}
  ],
  "turn_taking_count": 28
}
```

**算法**：
- `talk_time_sec` = sum(segment.end - segment.start) 按 speaker 分组
- `silence_ratio` = (total_duration - speech_duration) / total_duration
- `hot_words` = jieba 分词（**新依赖**，仅统计时按需懒加载）→ Counter.top(20) + 中英文停用词表
- `turn_taking_count` = 相邻 segment 说话人不一样的次数

**注意**：jieba 是新依赖，仅用于统计；用户可关闭统计功能避免引入。

### 6.3 `services/llm_gateway.py` — 可选 LLM 网关

```python
class LLMGateway:
    """可选 LLM 网关。禁用或不可用时不抛异常，调用方检查返回值。"""
    
    def __init__(self, config: LLMConfig):
        self.endpoint: str       # 默认 http://127.0.0.1:11434/v1
        self.model: str          # 默认 qwen2.5:1.5b
        self.timeout_sec: int    # 默认 60
        self.enabled: bool
        self._available_cache: Optional[bool] = None
    
    async def is_available(self) -> bool: ...       # 探测，5 分钟缓存
    async def summarize(self, segments) -> Optional[str]: ...
    async def extract_action_items(self, segments) -> Optional[list[str]]: ...
    async def generate_minutes(self, segments) -> Optional[str]: ...
```

**协议**：OpenAI 兼容 API（`/v1/chat/completions`）。
**支持后端**：Ollama、vLLM、LocalAI、llama.cpp server。

**隐私护栏**（启动时校验）：
```python
def _validate_endpoint(self):
    parsed = urlparse(self.endpoint)
    host = parsed.hostname
    if host not in self.allowed_hosts:           # 127.0.0.1, ::1, localhost
        if not ip_address(host).is_private:      # RFC1918 也可
            raise ConfigError(f"LLM endpoint {host} 不是内网/本机地址，"
                              f"本项目不允许调用公网 LLM。")
```

**Prompt 模板**（`services/llm_prompts.py`，可被前端读取+修改）：
```python
PROMPTS = {
    "summarize": "请根据以下转写生成 {max_words} 字以内的摘要：\n\n{transcript}",
    "action_items": "从以下转写中提取所有行动项，每条一行：\n\n{transcript}",
    "minutes": "请按「议题、决议、行动项」结构生成会议纪要：\n\n{transcript}",
}
```

**错误处理矩阵**：

| 场景 | 返回 | 前端行为 |
|---|---|---|
| `enabled=False` | `None` | 隐藏 LLM 按钮 |
| 探测失败（Ollama 没启动） | `None` | 按钮显示"未启用"，灰显 |
| 调用超时 | `LLMTimeoutError` | toast "LLM 响应超时" |
| 模型未下载 | `LLMModelMissingError` | 提示"请运行 ollama pull qwen2.5:1.5b" |
| 输入过长 | 自动分块 + 多次调用 | 显示进度 |
| 公网 endpoint | 启动失败 | settings 页红字提示 |

**Mock 模式**：环境变量 `LLM_MOCK=true` 启用，返回固定字符串。用于：
- 单元测试（永远不调真实 LLM）
- 前端开发
- CI（避免费用 + 隐私）

**API 端点**：

| 方法 + 路径 | 说明 |
|---|---|
| `GET /v1/llm/status` | `{enabled, available, endpoint, model}` |
| `POST /v1/llm/summarize` | body: `{session_id, max_words?}` |
| `POST /v1/llm/action-items` | body: `{session_id}` |
| `POST /v1/llm/minutes` | body: `{session_id}` |
| `GET /v1/llm/prompts` | 返回 prompt 模板 |
| `PUT /v1/llm/prompts` | 用户自定义 prompt |

**性能**：典型 1 小时会议 ≈ 8000 tokens 输入，1.5B 模型在 M2 Mac 上 ~10s。

### 7.2 错误处理与降级

| 故障点 | 降级行为 |
|---|---|
| 实时流：ASR 推理失败 | 该段跳过 + 记日志 + 下一段继续 |
| 实时流：声纹匹配失败 | 该段显示 `UNKNOWN`，不阻塞文本 |
| 实时流：ChromaDB 写失败 | 文本继续输出，告警"声纹学习未保存" |
| 上传：分段某段失败 | 整段标红、其余段正常返回 |
| 上传：LLM 不可用 | 跳过 LLM 步骤，基础导出仍可用 |
| 历史：SQLite 损坏 | 启动失败 + 备份 .bak + 提示用户 |
| LLM：超时 | 5xx + retry-after，前端 toast |
| 引擎切换：模型未下载 | 切回原引擎 + 提示"请先下载 X 模型" |
| 模型预下载：网络失败 | 报错 + 保留部分已下载的 + 提示重试 |

**统一错误响应 schema**：
```python
class ErrorResponse(BaseModel):
    code: str          # 'AUDIO_TOO_LONG' | 'LLM_UNAVAILABLE' | ...
    message: str       # 用户可见的中文
    detail: Optional[str]  # 开发者可见的英文
    retry_after: Optional[int]  # 秒
```

**WebSocket 错误**：用 `{"type": "error", "code": "...", "message": "..."}` 消息类型，不直接断连（除非致命）。

## 9. 风险与权衡

| 风险 | 影响 | 缓解 |
|---|---|---|
| jieba 引入增加安装复杂度 | 中 | 文档明示；用户可关闭统计功能；可选依赖 |
| 多页前端 vs SPA 体验 | 中 | 链接跳转足够；不需要复杂状态管理 |
| LLM 1.5B 模型质量不足 | 中 | 用户可换更大模型；推荐 7B；M1/M2 可跑 |
| SQLite 并发写入（多 WebSocket） | 低 | `WAL` 模式 + 单进程架构下不是问题 |
| ChromaDB 与 SQLite 数据不一致 | 中 | speaker_id 是唯一键；alias 表是覆盖层 |
| 模型预下载失败破坏离线体验 | 中 | 启动时检测；缺模型时清晰提示；不静默失败 |
| 前端纯静态 → 无法做登录态 | 低 | 定位"本地单人"，无需登录 |
| OpenAI 协议各家实现细节差异 | 中 | 测试覆盖 Ollama/vLLM；失败有明确错误码 |

## 10. 开放问题

> 这些问题在实施前需要进一步决定或 PoC 验证。

1. **Qwen3-ASR 流式能力**：是否能在不重启的情况下用 streaming mode 降低实时路径延迟？需 PoC。
2. **Ollama keep_alive 设置**：默认 5 分钟会被卸载；要不要 keep alive 24h？
3. **长段按标点切分**：v0.2 不做，v0.3 时决定切分阈值（5s / 10s？）
4. **历史清理策略**：7 天后"提醒"还是"自动归档"？v0.2 暂不做。
5. **多用户切换**：当 `client_id=A` 创建说话人后，`client_id=B` 看到的是同一份声纹库。当前是全局共享，是否要按 session_id 隔离？（当前 `BaseSpeakerEngine` 已支持 session_id 过滤，但 list 默认全局）
6. **CJK 字体**：Web 端导出文件被用户用 Word 打开时，Markdown 中文可能字体回退 — 要不要内置字体？
7. **导出文件命名**：`<title>_<date>.<ext>` 还是 UUID？要可配置。
